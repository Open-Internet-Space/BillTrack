I want to change…

Change the invoice logo, note or signing authority

  1. First open Admin → System Settings: ordinary invoice branding and wording are editable data.
  2. For layout changes, use the relevant body include and invoice style block.
  3. Compare single-month, consolidated and mixed-allottee HTML/PDF output before publishing.

invoice-letterhead · invoice-note · invoice-signature · admin-settings

Change invoice columns, amounts or page breaks

  1. For a visible column, edit the individual or consolidated charges include listed below.
  2. For a supplied value, follow invoice context to the Bill model; keep calculations out of templates.
  3. For page fitting, inspect common print styles and bulk-only breaks. Verify amounts, wording, page count and rendered output.

invoice-charges · invoice-dues · invoice-totals · invoice-data · invoice-styles · billing

Change a screen, form, menu or shared appearance

  1. Find the screen below, then open its feature component and supporting form/table blocks.
  2. Use shared components for reusable controls; App remains the composition/state coordinator.
  3. Follow the listed API/serializer/model when changing validation or saved data. Run feature and shared workflow tests.

interface · shell · styles · allottee-form · bill-forms · payment-form

Change password recovery or error messages

  1. Use LoginScreen or the reset template for appearance and labels.
  2. Use auth.py and the recovery model for security behavior; preserve the account budget and CSRF protection.
  3. Use shared API/server error handling for request failures; never add automatic write retries.

authentication · reset-screen · errors · api

Add or move a component

  1. Keep related UI, server behavior and tests grouped by feature. Preserve public routes and migration imports.
  2. Add or update the registry entry, including files, named parts, parents, settings and related tests.
  3. Run python scripts/build_component_map.py, then run it with --check. Both HTML and Markdown must be committed together.

modification-guide · tests

Change signup, account approval or email recovery

  1. Edit the account_security module for OTP, approval or email identity behavior.
  2. Edit the shared accounts templates for appearance; preserve CSRF, password hiding and generic recovery responses.
  3. Run email account tests against a file-backed SQLite test database, including concurrent OTP and approval cases.

authentication · email-accounts · reset-screen

Change reusable email templates or manual Mail Merge

  1. Edit named templates and default CC addresses in Admin before changing source.
  2. Use the email_drafts service for generated bill content and the frontend email-drafts feature for editing/copy behaviour.
  3. Run the feature tests and full suites; do not send real mail or change dispatch/reminder state.

email-drafts

Investigate or correct a business record

  1. Superusers use the existing model Admin with a written reason; review all related effects before confirming deletion.
  2. Search Activity log by date, actor, type, action or safe snapshot text; deleted records retain history. Passwords, OTPs, tokens and SMTP credentials are excluded.
  3. Use scripts/verify_activity_migrations.py on isolated databases for canonical and historical-chain upgrades. Do not replace either migration lineage or run a source-only production rollback.

activity-history · admin
