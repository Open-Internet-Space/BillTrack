Rollbacks and backup details

This page lists local recovery information only. It does not execute scripts, restore data, or download private archives.

A backup labelled for a feature can restore a whole earlier application version. It can remove later features too. Do not mix individual modules or use an older script against a newer installation.

Before any recovery

  1. Finish pending saves and preserve a fresh backup of the current records.
  2. On the server, check the installed source version: {{ version_command }}.
  3. Compare it with the snapshot's expected version, then read the named local instructions. Missing version metadata means manual review is required.
  4. Disable the relevant scheduled task before stopping it, so its repeating trigger cannot restart it during maintenance. Mail recovery also requires disabling the mail task.
  5. Use Administrator PowerShell on the server only after reviewing the procedure. Check login, balances, invoices and network access afterward.

Do not restore an older database merely to undo code: that can lose later work. Restoring old mail history can also make already-sent reminders eligible again. GitHub history is separate from local recovery.
